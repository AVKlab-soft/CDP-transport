# Архитектура системы автоматической обработки документов (EDC)

## 1. Общая концепция: "Однопроцессный конвейер с динамической подгрузкой"

Система представляет собой единый долгоживущий процесс (Роутер-Менеджер), который управляет очередью задач и хранит все данные в оперативной памяти. Модули подключаются как функциональные библиотеки, а не как отдельные процессы. Это обеспечивает минимальное потребление ресурсов (критично для 500 МБ ОЗУ) и мгновенную передачу данных между этапами обработки.

### Ключевые принципы
- **Модульность:** Каждый компонент изолирован. Изменение логики одного сайта не затрагивает ядро или другие сайты.
- **Работа в памяти:** Данные передаются через переменные PowerShell внутри одного процесса. Дисковые операции только для чтения входных файлов и записи финальных результатов.
- **Отсутствие зависимостей:** Чистый PowerShell + встроенные .NET классы (WebSocket). Никакого Python, Node.js или сторонних библиотек.
- **Целевая платформа:** Windows 10 x86, ungoogled-chromium (порт 9222).

## 2. Структура модулей

### 2.1. CDP Core (Ядро)
**Роль:** "Тупой" исполнитель. Не принимает решений, не знает о бизнес-логике.
**Входные данные:** 
- Текст запроса (строка).
- Пайплайн (объект/массив шагов).
- Контекст (селекторы, таймауты).
**Выходные данные:** Результат выполнения (текст ответа, статус).
**Функционал:**
- Подключение к WebSocket браузера.
- Выполнение примитивов: `inject_text`, `real_click` (эмуляция мыши для ant-design), `wait_element`, `extract_text`.
- Обработка ошибок на уровне DOM/JS.

### 2.2. Библиотека Пайплайнов (Конфигурация)
**Роль:** Хранение логики взаимодействия с конкретными сайтами.
**Формат:** JSON файлы (легковесные, читаемые).
**Структура:**
- Маппинг ключей (например, `provider: "qwen"`) на последовательность действий.
- Селекторы, тексты кнопок, условия ожидания вынесены сюда.
**Пример:**
```json
{
  "id": "qwen_thinking",
  "target_url": "chat.qwen.ai",
  "steps": [
    { "action": "set_mode", "value": "thinking" },
    { "action": "inject", "selector": "textarea", "source_var": "$input_text" },
    { "action": "click", "aria": "Отправить" },
    { "action": "wait_stable", "container": ".response-message-content" },
    { "action": "extract", "save_to": "$result" }
  ]
}
```

### 2.3. Роутер (Диспетчер)
**Роль:** Мозг системы. Принимает решение, какой пайплайн выполнить.
**Логика:**
1. Получает задачу от Менеджера очередей.
2. Парсит метаданные (из YAML-frontmatter в .md файле или из имени файла).
3. Сопоставляет метку (например, `network: qwen`) с соответствующим JSON-пайплайном.
4. Вызывает **CDP Core**, передавая текст и выбранный пайплайн.
5. Возвращает результат обратно в Менеджер.

### 2.4. Менеджер очередей (File Watcher)
**Роль:** Взаимодействие с файловой системой.
**Функционал:**
- Слушает папку `Input` через `FileSystemWatcher`.
- При появлении файла: читает содержимое в переменную -> удаляет файл (освобождает место).
- Передает контент и метаданные в **Роутер**.
- Получает результат от Роутера -> записывает итоговый файл в папку `Output`.

## 3. Поток данных (Data Flow)

1. **Старт:** Запуск главного скрипта `Main.ps1`. Инициализация переменных, подключение к браузеру (порт 9222).
2. **Вход:** Пользователь копирует `.md` файл в папку `Input`.
3. **Захват:** Менеджер считывает файл в переменную `$raw_content`, файл удаляется с диска.
4. **Анализ:** Роутер извлекает заголовок (например, `network: deepseek`).
5. **Маршрутизация:** Роутер загружает JSON-пайплайн для `deepseek`.
6. **Исполнение:** CDP Core получает текст и шаги пайплайна.
   - Подключается к вкладке.
   - Выполняет клики, ввод текста, ожидание через JS/CMD.
   - Извлекает ответ в переменную `$final_result`.
7. **Финал:** Менеджер записывает `$final_result` в файл `output_YYYYMMDD.md` в папку `Output`.
8. **Цикл:** Система возвращается в режим ожидания.

## 4. Технические ограничения и решения

| Ограничение | Решение |
| :--- | :--- |
| **500 МБ ОЗУ** | Один процесс. Отсутствие тяжелых объектов .NET. Сборка мусора после каждой задачи. |
| **Малый диск** | Файлы не хранятся в процессе обработки. Только вход -> память -> выход. |
| **Нет Python/Node** | Использование нативного `System.Net.WebSockets.ClientWebSocket` в PowerShell. |
| **UI Анти-паттерны** | Реализация `real_click` (mousePressed/mouseReleased) для обхода игнорирования JS-кликов. |
| **Разные сайты** | Изоляция логики в JSON. Добавление нового провайдера = новый JSON файл, правка ядра не требуется. |

---

## 5. План реализации (этапы)

1. **Прототип CDP Core:** Реализация подключения к WS и базовых методов (`evaluate`, `real_click`).
2. **Движок пайплайнов:** Парсер JSON и интерпретатор шагов.
3. **Интеграция с Роутером:** Логика выбора пайплайна по метаданным.
4. **Обвязка (Watcher):** Скрипт мониторинга папки и управления циклом.
5. **Тестирование:** Проверка на реальных сценариях (Qwen, DeepSeek и др.).
