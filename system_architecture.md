# Архитектура системы автоматизации: "Корпорация Агентов"

## 1. Общая концепция
Система представляет собой многоуровневую платформу для автоматизации бизнес-процессов с использованием ИИ-агентов. 
Ключевой принцип: разделение ответственности между уровнями, модульность, возможность независимой разработки и масштабирования.

---

## 2. Уровни архитектуры

### Уровень 1: Транспорт (CDP Core)
**Назначение:** Универсальный исполнитель действий в браузере.
**Роль:** "Руки" системы. Не принимает решений, только исполняет инструкции.
**Технологии:** 
- PowerShell + .NET (`System.Net.WebSockets` или `NamedPipes`)
- Браузер: `ungoogled-chromium` (x86) с флагом `--remote-debugging-port=9222`
- ОС: Windows 10 (без установки доп. ПО, Python и т.д.)
**Функционал:**
- Получает JSON-пайплайн (последовательность шагов).
- Выполняет действия: клик (real_click), ввод текста, скролл, ожидание элементов.
- Возвращает результат (текст со страницы, статус выполнения) в память.
**Особенности:**
- Работает в памяти (передача данных через переменные или Named Pipes).
- Не знает о бизнес-логике, агентах или провайдерах.
- Один экземпляр процесса обслуживает все запросы очереди.

### Уровень 2: Провайдеры (AI Engines)
**Назначение:** Адаптация запросов под конкретные нейросети.
**Роль:** "Шлюзы" к внешним моделям.
**Провайдеры:** DeepSeek, Qwen, Kimi, GPT и др.
**Функционал:**
- Формируют специфичные промпты и параметры для каждой модели.
- Используют Транспорт (Уровень 1) для взаимодействия с веб-интерфейсами провайдеров.
- Нормализуют ответы от разных моделей в единый формат.
**Важно:** Это не агенты, а технические обертки над API/веб-мордами.

### Уровень 3: Агенты (Business Logic)
**Назначение:** Реализация бизнес-логики и ролей сотрудников.
**Роль:** "Сотрудники" виртуальной корпорации (Копирайтер, Аналитик, Менеджер и т.д.).
**Количество:** 100+ агентов.
**Реализация:**
- Промпты + логика поведения (LangGraph или собственная реализация на PowerShell/другом языке).
- Комбинируются в бизнес-процессы (цепочки действий).
**Взаимодействие:**
- Работают с файлами (входные данные, промежуточные результаты, отчеты).
- Вызывают Провайдеров через Транспорт для получения ответов от ИИ.
- Управляют состоянием задачи (очереди, статусы).

### Уровень 4: Оркестрация и Интерфейс
**Назначение:** Управление потоками задач и взаимодействие с пользователем.
**Компоненты:**
- **Менеджер очередей:** Распределяет задачи между агентами, контролирует приоритеты.
- **Веб-интерфейс:** Панель управления для мониторинга, настройки процессов, просмотра логов.
- **Хранилище знаний:** База промптов, шаблонов пайплайнов, историй диалогов.

---

## 3. Принципы работы

### Модульность
- Каждый уровень независим. Изменение агента не требует правки Транспорта.
- Новые провайдеры добавляются как отдельные модули.
- Пайплайны для сайтов хранятся в JSON и загружаются динамически.

### Работа с данными
- **Внутри уровня 1 (Транспорт):** Данные передаются в памяти (переменные, Named Pipes), без записи на диск.
- **Между уровнями 2-3:** Агенты работают через файловую систему (вход/выход), что обеспечивает надежность, логируемость и возможность ручного вмешательства.
- **Конфигурация:** Хранится в файлах (JSON/YAML), загружается при старте или по требованию.

### Масштабируемость
- Поддержка множества одновременных задач через очередь.
- Возможность запуска нескольких экземпляров Транспорта для параллелизма (при наличии ресурсов).
- Агенты могут выполняться последовательно или параллельно в зависимости от бизнес-процесса.

### Ограничения и требования
- **ОС:** Windows 10 x86/x64.
- **Ресурсы:** До 500 МБ ОЗУ (оптимизация через однопроцессную модель для ядра).
- **Безопасность:** Профиль браузера сохраняется, авторизация выполняется пользователем вручную один раз.

## 4. Поток данных (Пример задачи)

1. **Пользователь** создает задачу в Веб-интерфейсе (или файл появляется в папке `Input`).
2. **Менеджер очередей** назначает задачу Агенту "Аналитик".
3. **Агент "Аналитик"** читает входной файл, формирует запрос для Провайдера "Qwen".
4. **Провайдер "Qwen"** формирует JSON-пайплайн для сайта `chat.qwen.ai` и передает его в **Транспорт**.
5. **Транспорт**:
   - Подключается к браузеру.
   - Выполняет шаги пайплайна (ввод текста, клик, ожидание).
   - Возвращает ответ нейросети в Провайдер.
6. **Провайдер** нормализует ответ и передает Агенту.
7. **Агент** обрабатывает ответ, записывает результат в файл `Output`, обновляет статус задачи.
8. **Веб-интерфейс** отображает готовый результат пользователю.

## 5. План развития

### Этап 1: Транспорт (CDP Core)
- Реализация базового подключения к Chromium через WebSocket.
- Создание библиотеки функций: `Click`, `Type`, `Wait`, `Extract`.
- Поддержка JSON-пайплайнов.

### Этап 2: Провайдеры
- Разработка модулей для Qwen, DeepSeek, Kimi, GPT.
- Унификация интерфейса вызова провайдеров.

### Этап 3: Базовые Агенты
- Создание 3-5 тестовых агентов (например, "Саммаризатор", "Переводчик", "Классификатор").
- Реализация простого бизнес-процесса (цепочка из 2 агентов).

### Этап 4: Оркестрация и Веб-интерфейс
- Разработка менеджера очередей.
- Создание веб-панели управления (на базе встроенного веб-сервера PowerShell или легковесного решения).

### Этап 5: Масштабирование
- Добавление новых агентов и провайдеров.
- Оптимизация производительности, внедрение кэширования.

## 6. Технические заметки

- **Ядро системы:** Единый долгоживущий процесс PowerShell (`Main.ps1`), управляющий очередью и транспортом.
- **Агенты:** Отдельные скрипты, вызываемые ядром по мере необходимости. Обмен данными — через файлы (для надежности и прозрачности) или Named Pipes (для скорости внутри одного узла).
- **Пайплайны:** JSON-файлы с описанием шагов для каждого сайта. Пример:
  ```json
  {
    "target_url": "chat.qwen.ai",
    "steps": [
      { "action": "inject_text", "selector": "textarea", "source_var": "$query" },
      { "action": "real_click", "aria_label": "Отправить" },
      { "action": "wait_stable_text", "container": ".response-content" },
      { "action": "extract_text", "target_var": "$result" }
    ]
  }
  ```
- **Отказоустойчивость:** Логирование всех этапов, возможность ручного перезапуска упавших агентов без остановки ядра.
